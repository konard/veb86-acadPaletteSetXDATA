# Проверка этапов 1–5 и TZXDATA (этапы 2–4) в AutoCAD 2021

Автоматическая сборка использует реальные API Autodesk, а WPF smoke-проверки
работают на Windows для .NET Framework 4.8 и .NET 8 без AutoCAD.
Следующие действия требуют установленного AutoCAD; CI не подтверждает их выполнение.

Основная цель — AutoCAD 2021 (сборка `net48`, API 24.0.0). Дополнительные цели:
AutoCAD 2024 с явно выбранным API 24.3.0 и AutoCAD 2025 (`net8.0-windows`).
Записывайте точную версию AutoCAD и обновления.

1. Распакуйте ZIP из Release в доверенную папку, через `NETLOAD` загрузите
   `acadPaletteSetXDATA.dll` в AutoCAD 2021. Проверьте сообщение
   `acadPaletteSetXDATA загружено. Команда XDATAPALETTE — показать/скрыть панель XDATA.`
   Панель не должна открываться автоматически. В отдельном сеансе проверьте
   загрузку без активной DWG: сообщение должно появиться один раз после открытия
   первой DWG, без повторов при переключении/открытии следующих документов.
   Для отдельных сборок разработки повторите сценарий в другом сеансе, скопировав
   три DLL нужной платформы и загрузив `AcadPaletteSetXData.AutoCAD.dll`.
2. Выполните `XDATAPALETTE`. Проверьте наличие одной панели «Свойства XDATA»,
   вертикальные вкладки справа: «Свойства», «XDATA», «Команды».
3. Выберите каждую вкладку мышью и клавиатурой. Без выделения «Свойства» неактивна,
   «XDATA» показывает пустое дерево, «Команды» — справку; сверху предложение выбрать объекты.
4. Повторно выполните команду: панель скрывается. Ещё раз: открывается та же панель,
   вкладка сохраняется. Повторите после закрытия нативной кнопкой ×.
5. Перетащите панель к левому и правому краям AutoCAD. Проверьте закрепление,
   переход в плавающее окно, изменение размеров и сворачивание кнопкой автоскрытия.
6. Установите `COLORTHEME=1`, затем `COLORTHEME=0`: нативная рамка и WPF-содержимое
   должны следовать теме. Текст и вкладки читаемы, выбранная вкладка не сбрасывается.
   Повторите смену темы со скрытой панелью, затем покажите её командой.
7. Откройте вторую DWG, переключитесь между документами и закройте их. Команда
   должна управлять той же панелью; простое переключение не меняет данные чертежей.
8. В **новой** DWG через `APPLOAD` загрузите `examples/stage3-selection.lsp`,
   выполните `XDATASTAGE3SAMPLE`. Пример создаёт LINE с ESMT XDATA и LWPOLYLINE
   с BobrovXDATA XDATA и XML XRecord, устанавливает `PICKFIRST=1` и выделяет оба объекта.
9. Сверху должно быть «Выделено объектов: 2 • Групповые свойства». Название/номер
   должны показывать «Разное», CD35 — разные количества и nullable-флаг.
   Выберите LINE/LWPOLYLINE в списке: параметры группы остаются теми же,
   а дерево «XDATA» показывает индивидуальные значения (Line A/021/1,2 и Cable B/022/2).
10. Во вкладке «XDATA» проверьте RegApp, коды 1000/1002, вложенный Material,
    ветку ExtensionDictionary / XRecord, ключ BobrovXDATA и XML-элементы/атрибуты.
    Раскройте/сверните ветки. Повторите смену объекта в этой вкладке.
11. Выделите каждый примитив мышью отдельно, добавляйте/удаляйте из набора Shift,
    выделите рамкой, нажмите Esc. Данные обновляются после завершения выбора;
    пустой набор очищает поля/материалы/дерево и отключает редактор.
12. Выделите объект без XDATA: поля пустые, нет материалов предыдущего объекта.
    Дополнительно проверьте динамический блок с XDATA на самом BlockReference:
    читаются данные экземпляра, а не определения блока.
13. При открытой панели создайте/активируйте вторую DWG, выберите другой объект,
    закройте активную DWG, затем все чертежи. Старая DWG не должна оставаться в панели.
    Выделение в неактивном документе не должно менять текущие параметры.
14. До первого вызова `XDATAPALETTE` выберите примитив: уже существующее выделение
    загружается. Повторите выбор со скрытой панелью и откройте её снова.
15. Проверьте подтверждение: просто войдите в поле «Разное» и выйдите, затем нажмите
    Enter без ввода. `DBMOD` и данные должны остаться прежними. Введите общее название:
    до Enter записи нет, после Enter оба дерева показывают новое название, но номера,
    количества и флаги остаются индивидуальными. Повторный Enter не создаёт ещё одну запись.
    Повторите изменение номера через потерю фокуса, типа через ComboBox, проекта после
    раскрытия секции. Backspace/Delete в пустом поле «Разное» и Enter явно задают пустое значение.
16. Через сторонний инструмент измените XDATA, выполните Undo/Redo при том же выделении:
    после завершения команды панель заново читает данные. Проверьте неизвестный RegApp,
    неизвестные поля и повреждённый XML — сырые значения видны, предупреждение в «XDATA».
17. Смените темы, вкладки, скройте/откройте панель. Выбранный объект/вкладка сохраняются.
    Уменьшите панель до 280×320: поля, дерево и примечания доступны с прокруткой.
18. Нажмите ✎ на CD35, задайте количество 7, Enter: во всех объектах количество 7,
    разные названия/номера/примечания сохраняются. Измените категорию и марку; проверьте
    перегруппировку и запись в соответствующие XDATA/XML, включая русские псевдонимы.
    Щёлкните флаг: выбранное состояние применяется ко всем, «Разное» исчезает только у флага.
19. Нажмите + Добавить: «Новый материал 1» появляется во всех деревьях. Переименуйте его
    и удалите через ×: марка исчезает у всех, остальные материалы сохранены. Для марки,
    существующей только на части объектов, все поля строки показывают «Разное»; удаление
    затрагивает только эту марку, изменение ячейки создаёт её на отсутствующих объектах.
20. После каждого вида записи выполните Ctrl+Z / REDO. Одна операция откатывает всю
    группу, повторное выполнение восстанавливает её. После завершения команды панель
    должна перечитать состояние. Проверьте отсутствие «Nothing to redo» после чтения панели.
21. Начните ввод, измените выделение/активную DWG до подтверждения: запись не должна
    перейти в другой документ или новый набор; старая операция отклоняется с сообщением.
    Повторите с удалённым/заблокированным объектом и некорректным XML: ошибка одной записи
    откатывает всю группу, поле возвращается к сохранённому состоянию.
22. Сохраните DWG, закройте и откройте снова: записанные значения должны сохраниться.
    Проверьте посторонние RegApp/поля/атрибуты XML и неизвестные XRecord до/после записи.
23. Закройте AutoCAD. Не должно появляться ошибок освобождения панели/подписок.

Этап 5 выполняет запись через отдельный `XDataWriter` с общей предварительной проверкой
и одной нативной транзакцией. Для точного сравнения буферов до записи, после Undo и
после Redo используйте [сценарий этапа 5](xdata-writing.md) и `examples/stage5-undo.lsp`.
Проверка Undo/Redo в живой DWG требует AutoCAD, который CI не запускает.
WPF-рендеры показывают содержимое панели отдельно от нативной рамки AutoCAD.

## TZXDATA, этап 2: схема в NOD

Описание формата и команд — [schema-nod.md](schema-nod.md). Перед сценарием задайте
переменную среды `XDATAPALETTE_TRACE=1` (до запуска AutoCAD), чтобы видеть загрузку и сброс
кэша схемы, загрузите `acadPaletteSetXDATA.dll` через `NETLOAD` и `examples/tzxdata-stage2-nod.lsp`
через `APPLOAD` (команда `VELECDUMP`). В отдельной папке подготовьте копию `examples/schema.json`
и `schema-conflict.json` — копию, где у параметра `Voltage` тип `Enum` заменён на `String`
(строку `"enum": "Voltage"` удалите), а объект параметра `Phase` удалён.

1. В новой DWG выполните `VELEC_SCHEMA_EXPORT`: сообщение «В чертеже нет схемы параметров»,
   файл не создаётся.
2. `VELEC_SCHEMA_IMPORT`, выберите `schema.json`. Режим не спрашивается (схемы нет),
   отчёт начинается с «Режим: Заменить (в чертеже нет схемы)» и перечисляет добавленные
   параметры, справочники и шаблоны. Ответьте `Нет`: `VELECDUMP` сообщает
   «В чертеже нет словаря VELEC».
3. Повторите импорт и ответьте `Да`: «Схема импортирована…». `VELECDUMP` показывает
   `VELEC/INFO`, `VELEC/PARAMETERS/...`, `VELEC/ENUMS/...`, `VELEC/TEMPLATES/...`;
   в `INFO` есть `storage`, `hash`, `importedAt`, `source` = `schema.json`, `mode` = `Replace`.
4. Выполните `U` один раз: словарь `VELEC` исчезает целиком, в трассировке — сброс кэша.
   `VELEC_SCHEMA_EXPORT` сообщает об отсутствии схемы. `REDO` возвращает схему, экспорт снова
   работает (кэш не устарел ни в одном направлении).
5. Повторите импорт того же файла в режиме «Объединить» и «Заменить»: в отчёте
   «Схема чертежа не изменится», после `Да` — «Схема чертежа уже совпадает с файлом;
   чертёж не изменён», `importedAt` в `VELECDUMP` прежний.
6. Нарисуйте отрезок и добавьте ему XDATA, использующую `Phase`:
   `(regapp "BobrovXDATA")`,
   `(entmod (append (entget (entlast)) '((-3 ("BobrovXDATA" (1000 . "Phase=ABC"))))))`.
   `VELEC_SCHEMA_IMPORT` → `schema-conflict.json` → «Объединить»: запрос по конфликту
   (`Оставить`/`Заменить`/`Поштучно`). Выберите `Поштучно`, затем для `Voltage` — `Оставить`:
   в отчёте «Voltage: в чертеже Enum, в файле String — оставить», `Phase` не удаляется.
   Ответьте `Нет`.
7. Тот же файл в режиме «Заменить»: в отчёте `~ Voltage (тип Enum → String)`,
   `- Phase [используется объектами: 1]`, блок «Удаляются из схемы, но используются объектами»
   и ошибки проверки — шаблоны ссылаются на удалённый `Phase`; запись не выполняется
   («Результат импорта содержит ошибки»).
8. Сохраните чертёж со схемой из шага 3 как DWG и как DXF (`SAVEAS`, «AutoCAD 2018 DXF»),
   закройте AutoCAD и переименуйте папку с JSON.
9. Откройте DWG и выполните `VELEC_SCHEMA_EXPORT` в `export-dwg.json`; откройте DXF и
   экспортируйте в `export-dxf.json`. Оба файла должны совпадать с `examples/schema.json`
   побайтно: `fc /b examples\schema.json export-dwg.json` (пример записан в канонической форме
   с переводами строк LF; если Git преобразовал их в CRLF, сравнивайте с `fc` без `/b`).
10. Откройте две DWG с разными схемами (или со схемой и без неё), переключайтесь и экспортируйте
    в каждой: у каждого документа своя схема и свой кэш. Закрытие документа без ошибок.
11. Измените текст в одном Xrecord через LISP (`entmod` записи `VELEC/PARAMETERS/Voltage`,
    поле `caption`): экспорт выводит предупреждение «контрольная сумма не совпадает» и
    записывает изменённую схему. Удалите `INFO`:
    `(dictremove (cdr (assoc -1 (dictsearch (namedobjdict) "VELEC"))) "INFO")` — экспорт
    отказывается («нет записи INFO»), импорт предлагает только «Заменить» и восстанавливает
    схему; `U` возвращает состояние без `INFO`.

Проверка этапа 2 в живой DWG требует AutoCAD. CI без AutoCAD проверяет формат записей,
round-trip через текст DXF, импорт, отчёт и запись только изменённых записей.

## TZXDATA, этап 3: XDATA v2

Описание формата, лимитов и кэша — [xdata-v2.md](xdata-v2.md). Задайте `XDATAPALETTE_TRACE=1`
до запуска AutoCAD, загрузите `acadPaletteSetXDATA.dll` через `NETLOAD`, импортируйте
`examples/schema.json` (`VELEC_SCHEMA_IMPORT`) и загрузите `examples/tzxdata-stage3-v2.lsp`
через `APPLOAD`. Откройте панель `XDATAPALETTE`.

1. Выполните `VELECV2SAMPLE`: создаются и выделяются три отрезка — A и B в формате v2 с общим
   `DEVICE_ID`, C в формате v1. В трассировке «Прочитано объектов: 3; …; кэш значений: 3,
   разборов XDATA: 3». `VELECXDATA` печатает XDATA: у A после `("BobrovXDATA" (1070 . 2) …)`
   идёт `("OtherApp" (1000 . "keep") (1071 . 42))`, коды значений — `1040` у `Power`,
   `1071` у `Poles`, `1070` у `Tray_Covered`.
2. Выберите A в списке объектов, вкладка «XDATA»: в «Диагностике» —
   `Old_Param: не описан в схеме`, `Current: тип значения не совпадает со схемой: ожидается
   Double (1040), записано 1000`, `Phase: ключ "ZZ" отсутствует в справочнике Phase` и
   `DEVICE_ID … повторяется у объектов <handle B>; этот объект сохраняет ID.` (у A handle меньше).
   У B — `DEVICE_ID … совпадает с объектом <handle A>; копии нужен новый GUID.` У C предупреждений
   v2 нет, во вкладке «Свойства» «Название» = «Объект v1»; у A и B поля v1 пустые.
3. Снимите выделение (`Esc`) и выделите те же три отрезка снова: «кэш значений: 3, разборов
   XDATA: 3» — XDATA не разбирается повторно. Снимите выделение, выполните `VELECV2TOUCH`
   (меняет `Device_Type` у B через `entmod`) и выделите три отрезка: «разборов XDATA: 4» —
   разобран только B, в «Свойствах»/«XDATA» видно новое значение. `U` и повторное выделение
   снова разбирают только B.
4. Выделите только A и измените «Название»: запись отклоняется сообщением «XDATA BobrovXDATA
   объекта … в формате v2; поля v1 не записываются.», XDATA A не меняется (`VELECXDATA`).
   Выделите A и C вместе и повторите: отказ для всей группы, C тоже не меняется. Выделите только
   C: запись проходит, `OtherApp` у A по-прежнему на месте.
5. Сохраните DWG, откройте снова: `VELECXDATA` показывает те же значения и коды групп.

Редактирование значений v2 из панели появится вместе с VST (этапы 5–6); запись v2, лимиты
255 байт/16 КБ, групповая запись одного поля и шаблоны проверяются автотестами
`XDataV2Tests` без AutoCAD. Проверка в живой DWG требует AutoCAD, который CI не запускает.

## TZXDATA, этап 4: `CalculatedString`

Описание формул, графа зависимостей и `Persist` — [calculated-string.md](calculated-string.md).
Задайте `XDATAPALETTE_TRACE=1` до запуска AutoCAD, загрузите `acadPaletteSetXDATA.dll` через
`NETLOAD`, импортируйте `examples/schema.json` (`VELEC_SCHEMA_IMPORT`; `GC_Name` =
`@@[GC_HeadDevice].@@[GC_HDGroup]`) и загрузите `examples/tzxdata-stage4-calc.lsp` через `APPLOAD`.
Откройте панель `XDATAPALETTE`.

1. Выполните `VELECCALCSAMPLE`: создаются и выделяются три отрезка. Трассировка после строки
   «Прочитано объектов: 3; …; разборов XDATA: 3» печатает результаты формул каждого объекта:
   `<handle A>: GC_Name = «ЩУ1.3»`, `<handle B>: GC_Name = «ЩУ1.4»` (записанное «устарело» не
   используется — у `GC_Name` нет `persist`), `<handle C>: GC_Name = «ЩУ2.»` (`GC_Name` входит в
   шаблон `DEVICE`, группа не задана — пустая строка).
2. Снимите выделение (`Esc`) и выделите те же три отрезка снова: «разборов XDATA: 3» — результаты
   формул те же, XDATA для вычисления не разбирается.
3. Снимите выделение, выполните `VELECCALCTOUCH` (меняет группу B на `3` через `entmod`) и выделите
   три отрезка: «разборов XDATA: 4» — разобран только B, трассировка показывает
   `<handle B>: GC_Name = «ЩУ1.3»`. `U` и повторное выделение возвращают `«ЩУ1.4»`.
4. Во вкладке «XDATA» у объектов нет диагностики формул: схема из примера не содержит циклов и
   неизвестных ссылок (импорт такой схемы отклоняется проверками `CyclicFormat` и `UnknownReference` этапа 1).

Изменение параметров v2 из панели и отображение формул в VST появятся на этапах 5–6. Подстановка
типов (раздел 7.2), циклы и неизвестные ссылки, пересчёт только зависимых, «Разное», запись
`Persist` в той же транзакции и отказ при 255 байтах проверяются автотестами
`CalculatedStringTests` без AutoCAD. Проверка в живой DWG требует AutoCAD, который CI не запускает.
