# Вычисляемые строки `CalculatedString` (TZXDATA, этап 4)

Этап 4 из [TZXDATA](../TZXDATA.md): параметр типа `CalculatedString` не вводится вручную, а
вычисляется по формуле `format` из значений других параметров объекта (раздел 7). Разбор формул,
граф зависимостей, обнаружение циклов, подстановка значений и запись `Persist` реализованы в
`Core` и тестируются без AutoCAD. Значения берутся из кэша значений этапа 3
([xdata-v2.md](xdata-v2.md)) — XDATA при вычислении не читается. Сторонние DLL не нужны.

| Файл | Назначение |
| --- | --- |

| `src/AcadPaletteSetXData.Core/SchemaCache.cs` | `SchemaSnapshot.Formulas` — формулы разбираются один раз на снимок схемы. |
| `src/AcadPaletteSetXData.Core/XDataPatchV2.cs` | Запись результатов `Persist` той же операцией, что меняет исходный параметр. |
| `src/AcadPaletteSetXData.Core/SelectionEdit.cs` | Операция `RecalculatePersisted` — пересчёт `Persist` (основа «Исправить: Persist» команды `VELEC_CHECK`, этап 9). |

## Синтаксис (раздел 7.1)

```text
@@[GC_HeadDevice].@@[GC_HDGroup]   →  ЩУ1.3
Напряжение @@[Voltage]             →  Напряжение 220 В      (подпись элемента ENUM)
Код @@[Voltage:key]                →  Код _AC_220V_50Hz      (ключ элемента ENUM)
E-mail@@@@host                     →  E-mail@@host           (@@@@ — экранированное @@)
```

`Id` в ссылке сравнивается без учёта регистра, как и везде в схеме. Разбор выполняет
`CalculatedFormat.Parse` этапа 1; незакрытая, пустая ссылка или модификатор, кроме `:key`, — ошибка формулы.

## Подстановка значений (раздел 7.2)

| Тип источника | Подставляется |
| --- | --- |
| `String` | значение как есть |
| `Integer` | число без разделителей (`3`) |
| `Double` | `Editor.Precision` знаков после запятой с разделителем текущей культуры (`2,50` в ru-RU); без `precision` — кратчайшая точная запись (`0,125`) |
| `Boolean` | «Да» / «Нет» |
| `Enum` | подпись элемента; с `:key` — ключ; ключ вне справочника — сам ключ |
| `CalculatedString` | результат той формулы (рекурсивно, в порядке графа) |
| `Table` | не подставляется: ошибка формулы, текст `@@[Id]` остаётся |

Отсутствующее значение заменяется значением по умолчанию: умолчание шаблона объекта (`TEMPLATE`)
важнее умолчания параметра; если умолчания нет — пустая строка. Значение с другим кодом группы
(`TypeMismatch`, этап 3) подставляется текстом, как оно записано.

## Граф зависимостей и циклы (раздел 7.3)

`FormulaSet.Build(SchemaSnapshot)` вызывается один раз на снимок схемы (`SchemaSnapshot.Formulas`,
ленивое свойство): после импорта схемы новый снимок строит новый граф, старые объекты кэша значений
сбрасываются вместе со снимком (этап 3).

- Каждая формула (`Formula`) хранит разобранные фрагменты, канонические `Id` ссылок (`References`)
  и список ошибок (`Errors`).
- Компоненты сильной связности (алгоритм Тарьяна) дают порядок вычисления — сначала формулы,
  на которые ссылаются (`Order`). Компонента из нескольких формул или ссылка формулы на себя — цикл:
  у каждого участника `InCycle` и ошибка `циклическая ссылка: A → B → A` (кратчайший путь).
- `Dependents(id)` — прямые и косвенные зависимые формулы `id` в порядке вычисления; результат
  кэшируется в графе.
- `Diagnostics` — строки `Id: ошибка` для всех формул схемы.

| Ошибка формулы | Когда | Результат |
| --- | --- | --- |
| `не задан format` | у `CalculatedString` нет `format` | пустая строка |
| `незакрытая ссылка @@[ в позиции N`, `недопустимая ссылка @@[…]` | `@@[Id` без `]`, `@@[]`, `@@[Id:abc]` | ошибочный фрагмент остаётся текстом, остальные ссылки подставляются |
| `неизвестная ссылка @@[X]` | `X` нет в схеме | `@@[X]` остаётся в тексте |
| `таблица X не подставляется в @@[X]` | ссылка на `Table` | `@@[X]` остаётся в тексте |
| `@@[X:key]: модификатор :key применим только к Enum` | `:key` у не-ENUM | подставляется значение |
| `циклическая ссылка: A → B → A` | цикл | ссылки внутри цикла остаются как `@@[Id]` |
| `зависит от ошибочного параметра X` | ссылка на ошибочную формулу вне цикла | подставляется текст `X` |

Проверка схемы этапа 1 (`SchemaValidator`, код `CyclicFormat`) не даёт импортировать схему с
циклом. Граф всё равно находит циклы и неизвестные ссылки: схема в NOD может быть изменена вне
плагина, а `ParameterSchemaJson.Load` возвращает схему вместе со списком ошибок.

## Вычисление на объекте: `ObjectCalculation`

```csharp
var values = cache.Get(snapshot);                 // ObjectValues из кэша этапа 3, без разбора XDATA
var calculation = new ObjectCalculation(values);   // все формулы схемы в порядке графа
calculation.Text("GC_Name");                       // "ЩУ1.3"
calculation.SetValue("GC_HDGroup", "4");           // пересчитывает только GC_Name и зависимые от него
calculation.SetTemplate("DEVICE");                 // смена шаблона меняет умолчания — пересчитывается всё
ObjectCalculation.Merge(selection, "GC_Name");     // общий текст или «Разное»
```

- Вычисление использует только `ObjectValues` кэша; `ObjectValuesCache.ParseCount` не растёт
  (проверяется тестом `CalculationUsesTheValueCacheWithoutReadingXData`).
- `SetValue` возвращает пересчитанные результаты; `EvaluationCount` считает вычисления формул —
  тест `ChangeOfASourceRecalculatesOnlyItsDependents` проверяет, что изменение `HD` пересчитывает
  только `Name` и `Full`, а изменение параметра вне формул не пересчитывает ничего. Задать вручную
  сам `CalculatedString` нельзя (`ArgumentException`, как и в `XDataPatch` этапа 3).
- Каждый объект выделения вычисляется отдельно; `Merge` возвращает общий результат или «Разное»
  (раздел 7.3, групповое редактирование).
- `Describe()` — строка трассировки: формулы, которые есть на объекте, в его шаблоне или ссылаются на
  его значения, например `2A1: GC_Name = «ЩУ1.3»`; `!` — ошибка формулы, `*` — устаревший `Persist`.

`SelectionViewModel.Calculations` строится при каждом обновлении выделения из тех же записей кэша.
Во вкладке «XDATA» объекта в «Диагностике» появляются ошибки формул, которые записаны на объекте
или входят в его шаблон (`U: неизвестная ссылка @@[Missing].`), и устаревшие значения `Persist`
(`Name: записано "…", вычислено "…"; …`). Отображение формул в VST (`ƒ`) — этапы 5–6.

## `Persist` (раздел 7.4)

Без `persist` результат не хранится: строка с тем же `Id` в XDATA игнорируется при чтении, всегда
показывается вычисленное значение. С `"persist": true` результат дублируется в XDATA строкой `1000`
для внешних программ (LISP, спецификации), но при чтении также используется вычисленное значение —
записанное считается производным (`CalculatedValue.Stored`, `IsStale`).

Результат записывается **той же операцией `XDataPatch`**, а значит той же транзакцией
`XDataWriter`, что и изменение исходного параметра; проверки 255 байт и 16 КБ охватывают и его:

| Операция | Какие `Persist` записываются |
| --- | --- |
| `SetParameter(id, …)` | зависимые от `id` (`Dependents`) — всегда, в том числе впервые |
| `RemoveParameter(id)` | зависимые от `id`, которые уже записаны на объекте или входят в шаблон |
| `SetTemplate(…)` | все `Persist`, которые записаны на объекте или входят в новый шаблон |
| `RecalculatePersisted()` | все `Persist`, которые записаны на объекте или входят в его шаблон |

- Формулы с ошибкой (цикл, неизвестная ссылка) не записываются: в XDATA не попадает текст с `@@[…]`.
- Результат длиннее 255 байт UTF-8 отменяет всю операцию для всех объектов:
  «…результат Name (Persist) длиннее 255 байт UTF-8; операция отменена.»
- `RecalculatePersisted` пропускает объекты без XDATA v2 (v1, другой версии, без раздела) вместо
  отказа для всей группы и не открывает на запись объекты, где ничего не изменилось (`XDataWriter`
  сравнивает данные до и после). На нём основан пересчёт `Persist` команды `VELEC_CHECK` (этап 9, [migration-check.md](migration-check.md)).
- Вычисление в `XDataPatch` использует значения кэша, если они относятся к той же схеме, иначе
  разбирает снимок транзакции; культура подстановки — текущая (`CultureInfo.CurrentCulture`).

## Допущения

- Отсутствующий `Persist` создаётся при изменении его источника, при назначении шаблона, который его
  содержит, и командой пересчёта; удаление источника не создаёт `Persist` на объектах, где его нет.
- Ключ ENUM вне справочника подставляется как есть; значение `TypeMismatch` — исходным текстом.
- `Double` без `Editor.Precision` форматируется кратчайшей точной записью (`"R"`) с разделителем
  культуры; `Integer` — без разделителей групп.
- Ошибка формулы распространяется на формулы, которые на неё ссылаются (`зависит от ошибочного
  параметра X`), чтобы `Persist` с некорректным текстом не записывался.
