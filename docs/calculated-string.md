# Вычисляемые строки `CalculatedString` (TZXDATA, этап 4)

Этап 4 из [TZXDATA](../TZXDATA.md): параметр типа `CalculatedString` не вводится вручную, а
вычисляется по формуле `format` из значений других параметров объекта (раздел 7). Разбор формул,
граф зависимостей, обнаружение циклов, подстановка значений и запись `Persist` реализованы в
`Core` и тестируются без AutoCAD. Значения берутся из кэша значений этапа 3
([xdata-v2.md](xdata-v2.md)) — XDATA при вычислении не читается.

`format`, который начинается с `=`, — формула NCalc (задача #43, раздел
[«Формульный режим»](#формульный-режим-задача-43)); остальные форматы работают, как прежде. Единственная
сторонняя библиотека — NCalc 7.4.0; в Release она встроена в `acadPaletteSetXDATA.dll`
([«Зависимость NCalc»](#зависимость-ncalc)).

## Синтаксис (раздел 7.1)

```text
@@[GC_HeadDevice].@@[GC_HDGroup]   →  ЩУ1.3
Напряжение @@[Voltage]             →  Напряжение 220 В      (подпись элемента ENUM)
Код @@[Voltage:key]                →  Код _AC_220V_50Hz      (ключ элемента ENUM)
E-mail@@@@host                     →  E-mail@@host           (@@@@ — экранированное @@)
```

`Id` в ссылке сравнивается без учёта регистра, как и везде в схеме. Разбор выполняет
`CalculatedFormat.Parse` этапа 1; незакрытая, пустая ссылка или модификатор, кроме `:key`, — ошибка формулы.

Это строковый режим: он действует для любого `format`, который **не** начинается с `=`, и не изменился.
Текст, который должен начинаться с `=`, записывается с `\=`: `\=@@[Number]` → `=1`
(убирается одна `\` перед начальным `=`: `\\=` → `\=`; `\=` не в начале строки — обычный текст).

## Подстановка значений (раздел 7.2)

| Тип источника | Подставляется |
| --- | --- |
| `String` | значение как есть |
| `Integer` | число без разделителей (`3`) |
| `Double` | `Editor.Precision` знаков после запятой с разделителем текущей культуры (`2,50` в ru-RU); без `precision` — кратчайшая точная запись (`0,125`) |
| `Boolean` | «Да» / «Нет» |
| `Enum` | подпись элемента; с `:key` — ключ; ключ вне справочника — сам ключ |
| `CalculatedString` | результат той формулы (рекурсивно, в порядке графа) |
| `Table` | не подставляется: ошибка формулы, текст `@@[Id]` остаётся |

Отсутствующее значение заменяется значением по умолчанию: умолчание шаблона объекта (`TEMPLATE`)
важнее умолчания параметра; если умолчания нет — пустая строка. Значение с другим кодом группы
(`TypeMismatch`, этап 3) подставляется текстом, как оно записано.

## Граф зависимостей и циклы (раздел 7.3)

`FormulaSet.Build(SchemaSnapshot)` вызывается один раз на снимок схемы (`SchemaSnapshot.Formulas`,
ленивое свойство): после импорта схемы новый снимок строит новый граф, старые объекты кэша значений
сбрасываются вместе со снимком (этап 3).

- Каждая формула (`Formula`) хранит разобранные фрагменты, канонические `Id` ссылок (`References`)
  и список ошибок (`Errors`).
- Компоненты сильной связности (алгоритм Тарьяна) дают порядок вычисления — сначала формулы,
  на которые ссылаются (`Order`). Компонента из нескольких формул или ссылка формулы на себя — цикл:
  у каждого участника `InCycle` и ошибка `циклическая ссылка: A → B → A` (кратчайший путь).
- `Dependents(id)` — прямые и косвенные зависимые формулы `id` в порядке вычисления; результат
  кэшируется в графе.
- `Diagnostics` — строки `Id: ошибка` для всех формул схемы.

| Ошибка формулы | Когда | Результат |
| --- | --- | --- |
| `не задан format` | у `CalculatedString` нет `format` | пустая строка |
| `незакрытая ссылка @@[ в позиции N`, `недопустимая ссылка @@[…]` | `@@[Id` без `]`, `@@[]`, `@@[Id:abc]` | ошибочный фрагмент остаётся текстом, остальные ссылки подставляются |
| `неизвестная ссылка @@[X]` | `X` нет в схеме | `@@[X]` остаётся в тексте |
| `таблица X не подставляется в @@[X]` | ссылка на `Table` | `@@[X]` остаётся в тексте |
| `@@[X:key]: модификатор :key применим только к Enum` | `:key` у не-ENUM | подставляется значение |
| `циклическая ссылка: A → B → A` | цикл | ссылки внутри цикла остаются как `@@[Id]` |
| `зависит от ошибочного параметра X` | ссылка на ошибочную формулу вне цикла | подставляется текст `X` |

Проверка схемы этапа 1 (`SchemaValidator`, код `CyclicFormat`) не даёт импортировать схему с
циклом. Граф всё равно находит циклы и неизвестные ссылки: схема в NOD может быть изменена вне
плагина, а `ParameterSchemaJson.Load` возвращает схему вместе со списком ошибок.

## Вычисление на объекте: `ObjectCalculation`

```csharp
var values = cache.Get(snapshot);                 // ObjectValues из кэша этапа 3, без разбора XDATA
var calculation = new ObjectCalculation(values);   // все формулы схемы в порядке графа
calculation.Text("GC_Name");                       // "ЩУ1.3"
calculation.SetValue("GC_HDGroup", "4");           // пересчитывает только GC_Name и зависимые от него
calculation.SetTemplate("DEVICE");                 // смена шаблона меняет умолчания — пересчитывается всё
ObjectCalculation.Merge(selection, "GC_Name");     // общий текст или «Разное»
```

- Вычисление использует только `ObjectValues` кэша; `ObjectValuesCache.ParseCount` не растёт
  (проверяется тестом `CalculationUsesTheValueCacheWithoutReadingXData`).
- `SetValue` возвращает пересчитанные результаты; `EvaluationCount` считает вычисления формул —
  тест `ChangeOfASourceRecalculatesOnlyItsDependents` проверяет, что изменение `HD` пересчитывает
  только `Name` и `Full`, а изменение параметра вне формул не пересчитывает ничего. Задать вручную
  сам `CalculatedString` нельзя (`ArgumentException`, как и в `XDataPatch` этапа 3).
- Каждый объект выделения вычисляется отдельно; `Merge` возвращает общий результат или «Разное»
  (раздел 7.3, групповое редактирование).
- `Describe()` — строка трассировки: формулы, которые есть на объекте, в его шаблоне или ссылаются на
  его значения, например `2A1: GC_Name = «ЩУ1.3»`; `!` — ошибка формулы, `*` — устаревший `Persist`.

`SelectionViewModel.Calculations` строится при каждом обновлении выделения из тех же записей кэша.
Во вкладке «XDATA» объекта в «Диагностике» появляются ошибки формул, которые записаны на объекте
или входят в его шаблон (`U: неизвестная ссылка @@[Missing].`), и устаревшие значения `Persist`
(`Name: записано "…", вычислено "…"; …`). Отображение формул в VST (`ƒ`) — этапы 5–6.

## `Persist` (раздел 7.4)

Без `persist` результат не хранится: строка с тем же `Id` в XDATA игнорируется при чтении, всегда
показывается вычисленное значение. С `"persist": true` результат дублируется в XDATA строкой `1000`
для внешних программ (LISP, спецификации), но при чтении также используется вычисленное значение —
записанное считается производным (`CalculatedValue.Stored`, `IsStale`).

Результат записывается **той же операцией `XDataPatch`**, а значит той же транзакцией
`XDataWriter`, что и изменение исходного параметра; проверки 255 байт и 16 КБ охватывают и его:

| Операция | Какие `Persist` записываются |
| --- | --- |
| `SetParameter(id, …)` | зависимые от `id` (`Dependents`) — всегда, в том числе впервые |
| `RemoveParameter(id)` | зависимые от `id`, которые уже записаны на объекте или входят в шаблон |
| `SetTemplate(…)` | все `Persist`, которые записаны на объекте или входят в новый шаблон |
| `RecalculatePersisted()` | все `Persist`, которые записаны на объекте или входят в его шаблон |

- Формулы с ошибкой (цикл, неизвестная ссылка) не записываются: в XDATA не попадает текст с `@@[…]`.
- Формула формульного режима, которая не вычисляется на объекте (деление на ноль и т. п.), тоже не
  записывается: в XDATA остаётся прежнее значение, `#ОШИБКА` туда не попадает.
- Результат длиннее 255 байт UTF-8 отменяет всю операцию для всех объектов:
  «…результат Name (Persist) длиннее 255 байт UTF-8; операция отменена.»
- `RecalculatePersisted` пропускает объекты без XDATA v2 (v1, другой версии, без раздела) вместо
  отказа для всей группы и не открывает на запись объекты, где ничего не изменилось (`XDataWriter`
  сравнивает данные до и после). На нём основан пересчёт `Persist` команды `VELEC_CHECK` (этап 9, [migration-check.md](migration-check.md)).
- Вычисление в `XDataPatch` использует значения кэша, если они относятся к той же схеме, иначе
  разбирает снимок транзакции; культура подстановки — текущая (`CultureInfo.CurrentCulture`).

## Формульный режим (задача #43)

`format`, который начинается с `=`, — выражение [NCalc](https://github.com/ncalc/ncalc): начальный `=` —
только признак режима, остальная часть вычисляется целиком. Текст и значения объединяются оператором
Excel `&`; смешивать шаблон строкового режима и выражение в одной строке нельзя.

```text
=@@[Power] * 2                                      →  25
="ЩУ" & @@[Number] & "." & @@[Group]                →  ЩУ1.3
="P=" & @@[Power] & " кВт"                          →  P=12,50 кВт
=IF(@@[Voltage] > 220, "Высокое", "Норма")          →  Высокое
=ROUND(@@[Length] / 1000, 2)                        →  12,35
\=@@[Number]                                        →  =1        (строковый режим: \= — текст «=»)
```

Формула разбирается **один раз на снимок схемы** вместе с графом (`FormulaSet.Build`): перевод
`@@[Id]` и `&`, разбор NCalc в дерево, проверка имён и функций. На объекте вычисляется готовое
дерево со значениями кэша; XDATA не читается, в XDATA формулы и код не пишутся.

### Синтаксис NCalc

| Что | Запись |
| --- | --- |
| Числа | `12`, `2.5`, `1e3` — разделитель дробной части всегда `.`, независимо от культуры |
| Строки | `"текст"` или `'текст'`; `\` экранирует следующий символ (`"a\"b"`) |
| Логические значения | `true`, `false` |
| Арифметика | `+` `-` `*` `/` `%`, скобки; `/` — деление с дробной частью (`7 / 2` → `3,5`) |
| Сравнения | `>` `<` `>=` `<=` `==` `!=` (`<>`); строки сравниваются с учётом регистра |
| Логика | `AND` `OR` `NOT` (без учёта регистра), `&&` `\|\|` `!` |
| Условия | `IF(условие, да, нет)`, `ifs(усл1, знач1, усл2, знач2, …, иначе)`, `условие ? да : нет`, `x in (220, 380)` |
| Объединение | `&` (Excel) — см. ниже |

Имена функций не зависят от регистра (`if`, `IF`, `Round`, `ROUND`).

### Ссылки `@@[Id]`

`@@[Id]` и `@@[Id:key]` вне строковых литералов передаются в NCalc **параметрами с типом**, а не
текстом: `=@@[Power] * 2` получает число, а не строку `"12,50"`.

| Тип схемы | Значение в формуле |
| --- | --- |
| `String` | строка |
| `Integer` | целое число |
| `Double` | число `double` |
| `Boolean` | `true` / `false` (не «Да»/«Нет») |
| `Enum` | подпись элемента — строка; с `:key` — ключ |
| `CalculatedString` | вычисленный текст той формулы (строка) |
| `Table` | запрещено: ошибка формулы |

- Значение берётся по прежним правилам `ObjectCalculation.Value()`: изменённое значение объекта, значение
  из XDATA (кэш), умолчание шаблона, умолчание параметра; если значения нет — `null`.
  Арифметика с `null` даёт пустой результат, сравнение `null == true` — «Нет»;
  `IF(isNull(@@[X]), 0, @@[X])` или `isNullOrEmpty(@@[X])` задают поведение явно.
- Строка, которая записана числом, в арифметике преобразуется в число (`"1" + 1` → `2`); строка,
  которая не является числом, — ошибка значения (`@@[Voltage] > 220` при подписи `220 В`). Для `Enum`
  сравнивайте строки: `@@[Voltage] == "220 В"` или `@@[Voltage:key] == "_AC_220V_50Hz"`.
- Ссылки внутри строк — текст: `="Текст @@[Power]"` → `Текст @@[Power]`; такие «ссылки» не попадают
  в `References`, граф и проверку схемы, а переименование параметра в редакторе схемы их не меняет.
- Остальное — как в строковом режиме: `Id` без учёта регистра, ссылки попадают в `Formula.References` и граф,
  `Dependents` пересчитывает только зависимые формулы в порядке графа, циклы и неизвестные ссылки —
  ошибки формулы. Имя без `@@[…]` (`Power`, `[Power]`) — ошибка «неизвестное имя».

### Объединение строк `&`

Перед разбором NCalc лексический преобразователь проходит выражение посимвольно (строковые литералы
копируются как есть, с учётом кавычек и `\`) и заменяет каждую цепочку операндов, соединённых
одиночным `&`, вызовом `CONCAT(a, b, …)`; `&&` остаётся логическим AND.

```text
="a && b" & (@@[Power] && 'c & d') && @@[Count] & 'x'
→ CONCAT("a && b", ([Power] && 'c & d')) && CONCAT([Count], 'x')
```

Приоритет `&` — как в Excel: слабее арифметики и сильнее сравнений. `="Σ=" & @@[Power] * 2 & " кВт"` →
`Σ=25 кВт`; `=@@[Number] & @@[Group] == "13"` → «Да». Операнды заканчиваются на сравнениях, логических
операторах, `?` `:`, запятых и скобках.

Операнд-ссылка (`& @@[Power] &`) подставляется **текстом строкового режима** (`Editor.Precision`,
«Да»/«Нет», подпись `Enum`); вычисленный операнд форматируется по правилам ниже.

Штатный `ExpressionOptions.StringConcat` NCalc 7.4.0 не используется — проверено на пакете
(`experiments/issue43/StringConcatProbe`): с ним `+` начинает склеивать строки с числами (`"1" + 2` →
`"12"` вместо `3`), числа форматируются без `Editor.Precision` (`12,5` вместо `12,50`), логические — как
`True`/`False`, а одиночный `&` в NCalc остаётся побитовым AND (`6 & 3` → `2`). Эквивалентная конфигурация —
функция `CONCAT`, вызываемая только преобразователем.

### Математические функции

| Функция | Значение |
| --- | --- |
| `ABS`, `SIGN`, `SQRT`, `POW(x, y)`, `EXP`, `LN`, `LOG(x, основание)`, `LOG10`, `IEEEREMAINDER(x, y)` | функции NCalc (`System.Math`) |
| `ROUND(x, n)` | округление от нуля: `ROUND(2.5, 0)` → `3` |
| `FLOOR`, `CEILING`, `TRUNCATE` | округление вниз, вверх, к нулю |
| `MIN(a, b)`, `MAX(a, b)` | меньшее / большее |
| `PI()` | π |
| `TEXT(x, "формат")` | число по формату .NET с разделителем культуры: `TEXT(@@[Power] / 3, "0.000")` → `4,167`, `TEXT(12345, "N0")` → `12 345` |
| `isNull(x)`, `isNullOrEmpty(x)` | проверка отсутствующего значения |

Другие функции NCalc (строковые, даты, `EscapeLike` и т. п.) и неизвестные имена — ошибка
«неизвестная функция X».

### Тригонометрия в градусах

`SIN`, `COS`, `TAN` принимают угол **в градусах**; `ASIN`, `ACOS`, `ATAN`, `ATAN2(y, x)` возвращают градусы.
Углы, кратные 90°, точны: `SIN(30)` → `0,5`, `COS(90)` → `0`, `SIN(180)` → `0`, `TAN(45)` → `1`;
`TAN(90)` — ошибка «TAN(90°) не определён». Перевод единиц — `RADIANS(x)` и `DEGREES(x)`
(`DEGREES(PI())` → `180`).

### Форматирование результата

| Результат | Текст |
| --- | --- |
| Только ссылка (`=@@[Power]`) | как в строковом режиме: `12,50` при `precision: 2`, «Да»/«Нет», подпись `Enum` |
| Дробное число | до 15 значащих цифр (`G15`) с разделителем текущей культуры: `=0.1 + 0.2` → `0,3`, `=1 / 3` → `0,333333333333333`; `-0` → `0` |
| Целое число | без разделителей групп: `=@@[Count] + 1` → `3` |
| `true` / `false` | «Да» / «Нет» |
| `null` | пустая строка |
| Строка | как есть |

Нужное число знаков задают `ROUND` (`=ROUND(@@[Length] / 1000, 2)` → `12,35`) или `TEXT`
(`=TEXT(@@[Length] * SIN(@@[Angle]), "0.0")` → `6172,5`). Культура — текущая
(`CultureInfo.CurrentCulture`), как и у строкового режима.

### Обработка ошибок

Ошибки текста формулы находятся при разборе схемы: они попадают в `Formula.Errors`,
`FormulaSet.Diagnostics` и в проверку схемы (`SchemaValidator`: `InvalidFormat`, `UnknownReference`,
`CyclicFormat`) — схема с такой ошибкой не импортируется и не применяется редактором схемы. Ошибки
значений зависят от объекта и находятся при вычислении (`CalculatedValue.EvaluationError`). В обоих
случаях текст результата — **`#ОШИБКА`**, причина — в «Диагностике» вкладки «XDATA» и в трассировке
`Describe()` (`F = «#ОШИБКА» !`).

| Ошибка | Пример |
| --- | --- |
| `пустая формула после =` | `=` |
| `ошибка синтаксиса выражения` | `=1 +` |
| `незакрытая строка в позиции N` | `="ЩУ` |
| `незакрытая скобка…`, `лишняя закрывающая скобка в позиции N` | `=(1 + 2`, `=1 + 2)` |
| `незакрытая ссылка @@[ в позиции N`, `недопустимая ссылка @@[…]` | `=@@[Power`, `=@@[Phase:caption]` |
| `недопустимый символ @ в позиции N…` | `=@Power` |
| `нет значения слева от &…`, `нет значения справа от &…` | `=& "a"`, `="a" &` |
| `неизвестное имя X…` | `=Power * 2` |
| `неизвестная функция X` | `=FOO(1)` |
| `неизвестная ссылка @@[X]` | `=@@[Missing] + 1` |
| `таблица X не подставляется в @@[X]` | `=@@[Rows] & "!"` |
| `@@[X:key]: модификатор :key применим только к Enum` | `=@@[Power:key]` |
| `циклическая ссылка: A → B → A` | `A = @@[B] + 1`, `B = @@[A] * 2` |
| `формула длиннее 4096 символов`, `формула слишком сложная…` | см. ограничения |
| `деление на ноль`, `переполнение или деление на ноль` | `=10 % @@[Count]` при `Count = 0`, `=1 / 0` |
| `значение не является числом…` | `=@@[Text] * 2` при тексте, `=SQRT("x")` |
| `несовместимые типы значений…`, `X: ожидается аргументов — N`, `TAN(90°) не определён` | `=SIN(1, 2)`, `=TAN(90)` |
| `зависит от ошибочного параметра X` | формула (любого режима), которая ссылается на ошибочную `X` |

- `IF` и `ifs` вычисляют только выбранную ветвь: `=IF(@@[Count] > 100, 10 % (@@[Count] - 2), "нет")` при
  `Count = 2` → `нет`, ошибки в невыбранной ветви нет.
- Ошибка значения исчезает вместе с причиной: после `SetValue("Count", 3)` формула и её зависимые снова
  вычисляются.
- Ошибочный результат не записывается в `Persist`: в XDATA остаётся прежнее значение (раздел 7.4).

### Примеры формул

Схема [`examples/issue43-formula-schema.json`](../examples/issue43-formula-schema.json) (проверяется
`SchemaCheck` в CI и тестом `TheExampleSchemaCalculates`), значения объекта A из
[`examples/issue43-formulas.lsp`](../examples/issue43-formulas.lsp):

| Параметр | `format` | Результат A |
| --- | --- | --- |
| `Designation` | `ЩУ@@[Number].@@[Group]` (строковый режим) | `ЩУ1.3` |
| `Label` | `="ЩУ" & @@[Number] & "." & @@[Group] & " — " & @@[Name]` | `ЩУ1.3 — Освещение` |
| `Total` (`persist`) | `=(@@[Power] + @@[Reserve]) * @@[Count]` | `26` |
| `TotalText` | `="P=" & @@[Total] & " кВт"` | `P=26 кВт` |
| `Load` | `=IF(NOT @@[Enabled], "отключено", IF(@@[Total] > 10 AND @@[Voltage:key] == "_AC_220V_50Hz", "большая", "норма"))` | `большая` |
| `LengthM` | `=ROUND(@@[Length] / 1000, 2)` | `12,35` |
| `Rise` | `=TEXT(@@[Length] * SIN(@@[Angle]), "0.0")` | `6172,5` |
| `Literal` | `\=@@[Number]` (строковый режим) | `=1` |

Изменение `Power` пересчитывает только `Total`, `TotalText` и `Load`; изменение `Enabled` — только `Load`.
`Total` — `CalculatedString`, поэтому в `Load` он приходит строкой `"26"` и сравнивается с числом
`10` численно.

Ручная проверка в AutoCAD: импортируйте схему (`VELEC_SCHEMA_IMPORT`), загрузите LSP, выполните
`VELECFORMULASAMPLE`, выделите линию A и сравните значения на вкладке «Свойства» с таблицей; поменяйте
`Power` в VST — пересчитываются только зависимые формулы, `VELECFORMULAXDATA` показывает записанный
`Total`. В редакторе схемы предпросмотр формулы показывает результат на выделенном объекте.

### Ограничения безопасности

- Формула — только выражение: нет переменных, присваиваний, циклов, вызовов .NET и доступа к файлам.
  Разрешены только перечисленные функции (белый список) и ссылки `@@[Id]` на параметры схемы
  того же объекта; любое другое имя — ошибка формулы.
- Формула хранится только в схеме NOD (`format`); в XDATA пишется только вычисленный текст `Persist`,
  из XDATA ничего не исполняется.
- Длина `format` — не больше 4096 символов (`FormulaExpression.MaxLength`); вложенность скобок и
  глубина дерева выражения — не больше 100 (`MaxDepth`). Скобки считает преобразователь до NCalc, без
  рекурсии, поэтому формула предельной длины не переполняет стек главного потока AutoCAD
  (тест `PathologicalFormulasDoNotExhaustTheStack` на стеке 256 КБ).
- Целочисленное переполнение — ошибка (`OverflowProtection`), а не неверное число; бесконечность и `NaN` —
  ошибка «результат не является числом».
- Кэш выражений NCalc отключён (`NoCache`): дерево хранится в снимке схемы и освобождается вместе с ним.

### Зависимость NCalc

- Пакет `NCalc` **7.4.0** закреплён (`[7.4.0]`) в `AcadPaletteSetXData.Core.csproj` (`netstandard2.0`);
  он совместим с `net48` и `net8.0-windows`. Формула разбирается `LogicalExpressionParser`
  (`NCalc.Parser.dll`) и вычисляется `EvaluationVisitor` (`NCalc.Core.dll`), других пакетов NCalc нет.
- Класс `NCalc.Expression` **не используется** (задача #57). Его конструктор создаёт статические
  `LogicalExpressionCache` и `LogicalExpressionFactory`, а их логгеры берутся из
  `Microsoft.Extensions.Logging.Abstractions`. В AutoCAD эту сборку часто уже загрузил другой компонент
  в старой версии 1.1.1.0, где нет `NullLoggerFactory`. Тогда любая формула, даже `=@@[power]`,
  давала «ошибка синтаксиса выражения: Не удалось загрузить тип
  "Microsoft.Extensions.Logging.Abstractions.NullLoggerFactory" из сборки … Version=1.1.1.0». Разбор и
  вычисление напрямую не обращаются к журналированию, поэтому версия `Microsoft.Extensions.Logging.Abstractions`
  в процессе AutoCAD больше не важна. Тест `LegacyLoggingTests` загружает ядро плагина и NCalc в
  отдельный `AssemblyLoadContext` вместе с `Microsoft.Extensions.Logging.Abstractions` 1.1.1. Он
  проверяет, что сам `new NCalc.Expression(…)` там падает с этой ошибкой, а формулы вычисляются и
  даже не запрашивают сборку журналирования. Проба `experiments/issue57/LegacyLoggingProbe` печатает
  то же самое.
- **Release** (`acadPaletteSetXDATA.dll`) остаётся одной DLL: NCalc и его зависимости встраиваются в неё
  ресурсами `Embedded.<имя>.dll` (цель `EmbedRuntimeAssemblies` в `acadPaletteSetXDATA.csproj`), а
  `EmbeddedAssemblies` (инициализатор модуля, `AppDomain.AssemblyResolve`) загружает их из памяти при
  первом обращении. CI проверяет, что в архиве одна DLL, а встроенные сборки замкнуты по ссылкам
  (`RegistrationSmoke`), и что предпросмотр формулы в WPF-проверке загрузил встроенный `NCalc.Core`.
- **Сборка для разработки** (три `AcadPaletteSetXData.*.dll`) кладёт `NCalc*.dll` и зависимости рядом;
  их нужно копировать в папку плагина вместе с тремя DLL. Сборка, запрошенная другой версией, ищется
  в этой папке по имени (у плагина, загруженного `NETLOAD`, нет binding redirects).
- Диагностика: переменная среды `ACADPALETTESETXDATA_TRACE_ASSEMBLIES=1` пишет каждую загрузку в
  трассировку (окно вывода отладчика).
- Не проверено в AutoCAD (на CI его нет): ресурс используется, только если CLR не нашёл сборку сам. Если
  в папке AutoCAD или уже в процессе есть другая версия `System.Memory`, `System.Text.Json` и т. п.,
  возможна вторая копия сборки в процессе или несовместимость с NCalc — она проявится как ошибка формулы
  («ошибка вычисления…») или исключение загрузки в трассировке выше. Типы NCalc не выходят за пределы
  плагина, поэтому конфликт типов с другими плагинами не ожидается.

## Допущения

- Отсутствующий `Persist` создаётся при изменении его источника, при назначении шаблона, который его
  содержит, и командой пересчёта; удаление источника не создаёт `Persist` на объектах, где его нет.
- Ключ ENUM вне справочника подставляется как есть; значение `TypeMismatch` — исходным текстом.
- `Double` без `Editor.Precision` форматируется кратчайшей точной записью (`"R"`) с разделителем
  культуры; `Integer` — без разделителей групп.
- Ошибка формулы распространяется на формулы, которые на неё ссылаются (`зависит от ошибочного
  параметра X`), чтобы `Persist` с некорректным текстом не записывался.
- Формульный режим: ссылка-операнд `&` и формула из одной ссылки сохраняют текст строкового режима
  (`Editor.Precision`, «Да»/«Нет»), чтобы `="P=" & @@[Power]` совпадало с `P=@@[Power]`; вычисленные
  числа — `G15` культуры. `CalculatedString` в формуле — строка; число в ней преобразуется NCalc при
  арифметике и сравнении с числом.
