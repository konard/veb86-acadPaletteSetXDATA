# ТЗ: модуль меню AutoCAD 2020–2024 — кнопка «Палитра XDATA»

Документ для разработчика нового модуля. Составлен в задаче
[#53](https://github.com/veb86/acadPaletteSetXDATA/issues/53): из плагина `acadPaletteSetXDATA`
удалено всё, что связано с меню и лентой AutoCAD (меню и вкладка **Bobrov** задачи #39). Меню
управления теперь строит отдельный модуль. Этот модуль не содержит логики панели: он только
создаёт элементы интерфейса AutoCAD, которые вызывают команды других модулей.

## 1. Цель

Добавить в AutoCAD 2020–2024 кнопку-переключатель видимости палитры «Свойства XDATA»:
первое нажатие показывает палитру, следующее скрывает, и так далее.

Кнопка должна быть доступна:

- в строке меню (пункт выпадающего меню);
- на ленте (кнопка на панели вкладки).

Название меню, вкладки и панели задаёт заказчик. По умолчанию, как в задаче #39:
меню **Bobrov**, вкладка ленты **Bobrov**, панель **Палитра XDATA**, кнопка **Палитра XDATA**
с подсказкой «Показать или скрыть панель «Свойства XDATA» (XDATAPALETTE)».

## 2. Контракт с плагином acadPaletteSetXDATA

Плагин предоставляет одну команду, и модуль меню использует только её:

| Что | Значение |
| --- | --- |
| Команда | `XDATAPALETTE` (глобальное имя, без локализации) |
| Действие | Переключатель: если палитры нет или она скрыта — показывает (при первом вызове создаёт), если видна — скрывает. Палитра, закрытая крестиком в заголовке, считается скрытой |
| Флаги | `CommandFlags.Session \| CommandFlags.UsePickSet`: выполняется в контексте приложения и не сбрасывает текущий выбор объектов |
| Ввод | Не запрашивает ничего в командной строке; ошибки пишет одной строкой «Не удалось открыть панель XDATA: …» |
| Загрузка плагина | Пакет `acadPaletteSetXDATA.bundle` (`PackageContents.xml`): `LoadOnAutoCADStartup="True"` и `LoadOnCommandInvocation="True"`, команда объявлена в `<Commands>`. Если плагин ещё не загружен, вызов `XDATAPALETTE` загружает его |

Команд `XDATAPALETTE_ON` / `XDATAPALETTE_OFF` больше нет (удалены в задаче #53). Модуль не должен
их вызывать.

Модуль меню **не должен**:

- ссылаться на `acadPaletteSetXDATA.dll`, загружать её (`NETLOAD`) или вызывать её типы через отражение;
- искать палитру по GUID или заголовку и менять её видимость напрямую;
- зависеть от версии плагина: любое изменение внутренностей плагина при сохранённой команде
  `XDATAPALETTE` не должно требовать изменений в модуле меню.

## 3. Целевые версии и окружение

- AutoCAD 2020, 2021, 2022, 2023, 2024 x64 (серии `R23.1`–`R24.3`), включая вертикальные продукты на их основе.
  Основная проверенная цель плагина — AutoCAD 2021.
- AutoCAD 2025 и новее (.NET 8) — вне объёма, как и для самого плагина.
- Если в модуле есть .NET-код: `net48`, x64, NuGet `AutoCAD.NET` 24.0.0 (как у плагина) с
  `<Private>false</Private>` / `ExcludeAssets=runtime` — сборки AutoCAD в поставку не входят.
  На машине с AutoCAD 2020 должен быть установлен .NET Framework 4.8 (то же требование, что у плагина).
- Локализованный AutoCAD (русский и английский): в макросах только глобальные имена команд с `_`.

## 4. Рекомендуемая реализация: частичный CUIX в пакете Autoloader

Предпочтительный вариант — без .NET-кода:

1. Создать частичный файл адаптации (например, `BobrovMenu.cuix`) в редакторе `CUI` AutoCAD 2020
   (файл, созданный в самой старой целевой версии, открывается в новых).
2. В нём:
   - команда (Command) **Палитра XDATA**, макрос см. п. 5, значки 16×16 и 32×32;
   - выпадающее меню **Bobrov** с этой командой;
   - вкладка ленты **Bobrov** с панелью **Палитра XDATA** и большой кнопкой этой команды.
3. Поставлять отдельным пакетом `<Имя>.bundle` в `%APPDATA%\Autodesk\ApplicationPlugins`
   (или `%ProgramData%\Autodesk\ApplicationPlugins`), по образцу
   [PackageContents.xml](../installer/acadPaletteSetXDATA.bundle/PackageContents.xml) плагина:

   ```xml
   <ComponentEntry AppName="BobrovMenu" ModuleName="./Contents/BobrovMenu.cuix" />
   <RuntimeRequirements OS="Win64" Platform="AutoCAD*" SeriesMin="R23.1" SeriesMax="R24.3" />
   ```

   Свои `ProductCode` / `UpgradeCode` (новые GUID), не совпадающие с плагином.

Почему так. Меню и вкладку частичного CUIX AutoCAD загружает сам; они переживают смену рабочего
пространства (`WSCURRENT`), повторную загрузку меню (`MENULOAD`) и закрытие/открытие ленты
(`RIBBONCLOSE` / `RIBBON`) без кода модуля. Это исключает класс ошибок задачи #47 (см. п. 7).

Альтернатива — .NET-модуль, строящий меню через COM (`MenuGroups`, `MenuBar`) и вкладку через
`AdWindows` (`ComponentManager.Ribbon`), как было в задаче #39. Её допускается выбрать только при
обосновании (например, если меню формируется динамически), с обязательным выполнением п. 7.
Для кнопки ленты в .NET-варианте команда запускается так:
`Application.DocumentManager.MdiActiveDocument?.SendStringToExecute("_XDATAPALETTE ", true, false, false)`.

## 5. Макрос кнопки

Базовый макрос (как в задаче #39):

```text
^C^C_XDATAPALETTE 
```

`^C^C` отменяет активную команду, `_` выбирает глобальное имя, пробел в конце завершает ввод.

Команда плагина объявлена с `UsePickSet` и показывает свойства выбранных объектов. В AutoCAD
`^C^C` без активной команды может снять текущий выбор (ручки). Поэтому рекомендуется макрос,
который отменяет только активную команду:

```text
$M=$(if,$(getvar,cmdactive),^C^C)_XDATAPALETTE 
```

Выбор макроса подтвердить проверкой 3 из п. 8: выбранные до нажатия объекты должны остаться
выбранными и отобразиться в палитре.

## 6. Состояние «включено/выключено» на кнопке

Обязательно: кнопка — обычная кнопка-переключатель, которая каждый раз вызывает `XDATAPALETTE`.
Подпись и значок нейтральные («Палитра XDATA»), без «Включить»/«Выключить».

Не входит в объём: индикация текущего состояния (нажатая кнопка, галочка в меню). Плагин сейчас
не публикует признак видимости палитры, а угадывать его по нажатиям нельзя — пользователь
закрывает палитру и крестиком. Если индикация понадобится, сначала нужна отдельная задача в
`acadPaletteSetXDATA` на публичный признак (например, LISP-функция или пользовательская
системная переменная, пригодная для DIESEL `$(if,…,!.)` в меню). Модуль меню будет только читать его.

## 7. Требования к поведению при запуске (уроки задач #39 и #47)

Обязательны для любого варианта реализации:

1. Модуль ничего не пишет в командную строку при запуске AutoCAD и не запускает команд, сценариев или LISP.
2. Модуль не меняет `MENUBAR`, `WSCURRENT`, рабочее пространство и основной CUIX пользователя.
   Если строка меню скрыта (по умолчанию в AutoCAD 2021+), кнопка доступна на ленте; показывать
   строку меню — решение пользователя.
3. Только для .NET-варианта:
   - любые изменения меню/ленты выполнять на `Application.Idle`, когда есть активный чертёж, ни
     один чертёж не открывается (между `DocumentCreateStarted` и
     `DocumentCreated`/`DocumentCreationCanceled`), `Application.IsQuiescent` и
     `Editor.IsQuiescent` истинны, а `Document.CommandInProgress` пуст. Образец —
     `StartupReadiness` (`src/AcadPaletteSetXData.Core/StartupScheduling.cs`) и
     `src/AcadPaletteSetXData.AutoCAD/AutoCadStartup.cs`;
   - после `WSCURRENT` только проверять наличие меню/вкладки и добавлять недостающее;
     изменения, вызванные самим модулем, не должны снова запускать установку (иначе — бесконечный
     цикл и мерцание «Выберите объекты», как в задаче #47);
   - повторная загрузка модуля не дублирует пункты меню и вкладки.
4. Запуск AutoCAD двойным щелчком по DWG открывает чертёж без запросов в командной строке.

## 8. Приёмка

Проверяется вручную в установленном AutoCAD (минимум 2021, желательно 2020 и 2024), с
установленными пакетами `acadPaletteSetXDATA.bundle` и модуля меню:

1. Меню **Bobrov** в строке меню (`MENUBAR` = 1) и вкладка **Bobrov** на ленте содержат кнопку
   **Палитра XDATA** со значком и подсказкой.
2. Нажатие кнопки показывает палитру «Свойства XDATA», повторное — скрывает; то же из меню.
   После закрытия палитры крестиком кнопка снова её показывает (одно нажатие).
3. Выбрать объект, нажать кнопку: объект остаётся выбранным, палитра показывает его свойства.
4. Нажатие во время активной команды (например, `LINE`) отменяет её и переключает палитру.
5. Без загруженного плагина (убрать `LoadOnAutoCADStartup` или выполнить первым действием после
   запуска): нажатие загружает плагин и показывает палитру.
6. Без установленного плагина: AutoCAD сообщает о неизвестной команде; модуль не падает и не выводит
   других ошибок.
7. Смена рабочего пространства (`WSCURRENT`), `RIBBONCLOSE` → `RIBBON`, `MENUBAR` 0 → 1, повторный
   запуск AutoCAD: кнопка на месте, без дублей.
8. Запуск AutoCAD двойным щелчком по DWG и с `acaddoc.lsp`, выполняющим команду: чертёж открывается
   сразу, нет «Выберите объекты», в командной строке нет сообщений модуля.
9. Русская и английская версии AutoCAD: кнопка работает (глобальное имя `_XDATAPALETTE`).
10. Удаление пакета модуля убирает меню и вкладку; плагин и команда `XDATAPALETTE` продолжают работать.

Для .NET-варианта дополнительно — модульные тесты логики установки на заглушках (образец —
`tests/AcadPaletteSetXData.AutoCAD.Tests`) и проверка поставки: в пакете нет сборок AutoCAD SDK.

## 9. Результат работы

- Пакет `<Имя>.bundle` (CUIX или DLL, значки, `PackageContents.xml`), инструкция по установке и удалению.
- Исходники (CUIX хранится в репозитории как есть; при .NET — проект и тесты).
- Протокол приёмки по п. 8 с указанием версий AutoCAD и снимками меню и ленты.
