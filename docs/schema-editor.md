# Редактор схемы (TZXDATA, этап 8)

Этап 8 из [TZXDATA](../TZXDATA.md) (раздел 9) — модальное WPF-окно для правки схемы параметров чертежа без
JSON: параметры, справочники ENUM, шаблоны и импорт/экспорт. Окно открывают команда `VELEC_SCHEMA_EDIT` и
пункт «Редактор схемы…» меню кнопки «⚙» панели. Все правки копятся в **черновике**; «Применить» проверяет
черновик (раздел 4.5) и записывает его в `NOD/VELEC` одной транзакцией — один шаг Undo, «Отмена» чертёж не
меняет. Новые параметры, ENUM и шаблоны сразу доступны в VST: кэш схемы сбрасывается, панель перечитывает
выделение после команды. Сторонние DLL не нужны: окно входит в `acadPaletteSetXDATA.dll`.

## Открытие окна

```text
«⚙» → «Редактор схемы…» → SendStringToExecute("_VELEC_SCHEMA_EDIT ")
VELEC_SCHEMA_EDIT (UsePickSet, Redraw) → схема из кэша документа, SchemaUsage по всем объектам чертежа,
  снимки объектов PICKFIRST → SchemaEditorViewModel → Application.ShowModalWindow(SchemaEditorWindow)
  «Применить» → SchemaEditorViewModel.Apply(AutoCadSchemaNodTransaction) → одна транзакция NOD → сброс кэша
  «Отмена» / закрытие → «Редактор схемы закрыт; чертёж не изменён.»
```

- Меню «⚙»: «Редактор схемы…», «Импорт JSON…», «Экспорт JSON…» — те же команды, что в командной строке.
  Без AutoCAD (предпросмотр, тесты) кнопка недоступна.
- Схема без ошибок не нужна для открытия: замечания чтения NOD выводятся в командную строку. Повреждённую
  схему (раздел 5.2) окно не открывает — её восстанавливают `VELEC_SCHEMA_IMPORT` в режиме «Заменить».
- Выбранные до команды объекты остаются выбранными (`Redraw`) и дают предпросмотр формул; панель после
  команды перечитывает выделение и показывает новые параметры.
- Тема окна — тема AutoCAD (`COLORTHEME`), как у панели.
- `INFO` записанной схемы: `source` = `Редактор схемы`, `mode` = `Edit`.

## Вкладки (раздел 9)

| Вкладка | Содержимое |
| --- | --- |
| «Параметры» | Список с поиском по `Id`, подписи, группе, типу и описанию; `+`, `−`, `↑`, `↓`. Форма полей раздела 4.1: `Id`, тип (типы реестра), подпись, описание, группа, умолчание, справочник; для `CalculatedString` — формула с подсказкой `@@[` (список параметров вставляет `@@[Id]` у курсора), предпросмотр на первом выбранном объекте и `Persist`; для `Table` — `Columns`, `GroupBy`, `Key`; редактор VST (`Unit`, `Precision`, `Min`, `Max`, `MaxLength`, `Multiline`, `AllowCustom`, `ReadOnly`, `VstColumn`). Ниже — число объектов чертежа с этим параметром, шаблоны и ссылки (формулы, таблицы). |
| «ENUM» | Список справочников; `Id`, подпись, параметры, которые его используют; таблица `Key`/`Caption` с числом объектов на ключ, `+ Ключ`, `−`, `↑`, `↓`. |
| «Шаблоны» | Список шаблонов; `Id`, подпись, `EntityTypes` (через запятую), число объектов с шаблоном; «Все параметры» ⇄ «Параметры шаблона» (`→`, `←`, двойной щелчок), порядок `↑`/`↓`, переопределение `Default` выбранного параметра шаблона с подсказкой об умолчании параметра. |
| «Импорт/экспорт JSON» | «Импорт: объединить…», «Импорт: заменить…» — файл в черновик по правилам `VELEC_SCHEMA_IMPORT` (раздел 5.3) с отчётом; «Экспорт черновика…» — черновик в JSON (UTF-8 без BOM). Чертёж меняет только «Применить». |

Под вкладками — ошибки и предупреждения черновика (`SchemaValidator` раздела 4.5 и ошибки ввода чисел)
и список изменений относительно схемы чертежа (`+ параметр Room`, `~ шаблон DEVICE`, `− справочник Phase`).
«Применить» доступно, когда черновик изменён и ошибок нет; строка состояния показывает итог и причину отказа.

## Защита данных чертежа

| Действие | Правило |
| --- | --- |
| Удаление параметра | Запрещено, если параметр хранится в объектах чертежа («Параметр Power хранится в объектах чертежа (2) — удаление запрещено.») или на него ссылаются шаблон, формула, таблица — до удаления ссылок. |
| Смена `Id` параметра или шаблона | Запрещена, если объекты хранят прежний `Id`; `Id` неиспользуемого объекта меняется вместе со ссылками (шаблоны, формулы, `Columns`, `Enum`). |
| Удаление справочника | Запрещено, пока на него ссылаются параметры. |
| Удаление или переименование ключа ENUM | Если ключ хранится в объектах, только после подтверждения с их числом; умолчания с удалённым ключом становятся ошибкой до исправления. |
| Удаление шаблона | Запрещено, если шаблон назначен объектам. |
| Импорт «Заменить» | Отказ, если удалит используемые объекты; черновик не меняется (как у команды). |
| Ввод не числа в числовое поле | Текст остаётся в поле, ошибка в списке, «Применить» недоступно. |
| «Отмена», закрытие окна | При изменённом черновике — вопрос «Черновик схемы изменён. Закрыть редактор без записи в чертёж?». |

Число объектов считается по всем примитивам с `BobrovXDATA` (v2 и v1) в пространствах модели, листах и
определениях блоков при открытии окна.

## Запись

`Apply` вызывает тот же `SchemaNodWriter`, что импорт: пишутся только изменённые записи `VELEC` и `INFO`,
удалённые объекты стираются, всё в одной транзакции под блокировкой документа — один шаг Undo
(`VELEC_SCHEMA_EDIT`). Черновик с ошибками не записывается. Если черновик совпадает со схемой чертежа,
ничего не пишется. После записи кэш схемы документа сбрасывается: VST, «Шаблон ▾» и `+ Параметр`
используют новую схему.

```text
Команда: VELEC_SCHEMA_EDIT
Схема записана: объектов NOD 3, удалено 0; Параметров: 27, справочников: 3, шаблонов: 4; изменений: 2. Отмена — одной командой U.
```

## Проверка

```bash
DOTNET_ROLL_FORWARD=Major dotnet test tests/AcadPaletteSetXData.Core.Tests -c Release
# Windows: рендеры в каталог
dotnet run --project experiments/AcadPaletteSetXData.WpfSmoke -c Release -f net48 -- artifacts/screenshots/net48
```

WPF smoke (CI, net48 и net8) проверяет: кнопку «⚙» без хоста и с ним, меню из трёх команд и запуск
`VELEC_SCHEMA_EDIT`; настоящее окно в `ShowDialog` — первый параметр при открытии, предпросмотр
`GC_Name` = «ЩУ1.3» на выбранном объекте, отказ удалить используемый `Power`, ключи ENUM, списки
шаблона, ошибку `Id` с недоступным «Применить», импорт «Объединить» с отчётом, «Применить» →
`DialogResult = true` и запись черновика в NOD в памяти одной транзакцией; «Отмена» изменённого
черновика с вопросом → `false`; светлую тему. RegistrationSmoke проверяет, что `VELEC_SCHEMA_EDIT`
зарегистрирована в выпускной DLL. Ручная проверка в AutoCAD —
[autocad-verification.md](autocad-verification.md#tzxdata-этап-8-редактор-схемы), рендеры —
[screenshots](screenshots/README.md).

## Ограничения этапа

- `ShowModalWindow`, Undo/Redo и запуск из меню «⚙» в живом AutoCAD CI не проверяет — только ручной сценарий.
- Число объектов считается при открытии окна; объекты, изменённые другим документом, не учитываются.
- Таблица `Columns` задаётся списком `Id` через запятую; отдельного редактора столбцов нет.
- Перенос старых форматов — `VELEC_MIGRATE` (этап 9).
