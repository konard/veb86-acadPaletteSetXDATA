# VST вкладки «Свойства»: редактирование (TZXDATA, этап 6)

Этап 6 из [TZXDATA](../TZXDATA.md) превращает VST этапа 5 ([vst.md](vst.md)) в редактор: значения
вводятся прямо в колонке «ЗНАЧЕНИЕ», флажки, `×`/`✎`/`+ Добавить` и «+ Параметр» работают. Изменение
записывается во **все** объекты выделения одной транзакцией через `XDataWriter`
([xdata-v2.md](xdata-v2.md)); затем выделение перечитывается, а `CalculatedString`
([calculated-string.md](calculated-string.md)) пересчитывается сразу. Сторонние DLL не нужны.

| Файл | Назначение |
| --- | --- |
| `src/AcadPaletteSetXData.Core/PropertyGrid.cs` | Редактор строки (`PropertyRow.Editor`, `EditText`, `Options`, `Unit`), команды `Commit`, `Cancel`, `SetFlag`, `DeleteRow`, `EditRow`, `AddRow`, `AddParameter`, сообщения об ошибках ввода и записи. |
| `src/AcadPaletteSetXData.Core/SelectionViewModel.cs` | `CanWrite`, `Error`, `RequestEdit` → событие `EditRequested`. |
| `src/AcadPaletteSetXData.Core/SelectionController.cs` | Запись `SelectionEdit` через `ISelectionWriter`, перечитывание выделения и кэша значений; ошибка — с прежними значениями. |
| `src/AcadPaletteSetXData.Core/XDataPatchV2.cs` | `XDataPatch.Check`: та же проверка типа, `Min/Max`, списка и длины, что и при записи, — до транзакции. |
| `src/AcadPaletteSetXData.UI/PropertyGridView.xaml(.cs)` | Редакторы ячейки в фокусе, флажки, кнопки `×` `✎` `+ Добавить`, меню «+ Параметр», клавиатура. |
| `tests/AcadPaletteSetXData.Core.Tests/GroupEditingV2Tests.cs` | Перенесённые тесты этапа 4 палитры (`GroupEditingTests`) для v2 с настоящим `XDataWriter`. |

## Редакторы (раздел 8.3)

Редактор создаётся только у **выделенной** строки: у остальных строк колонка 2 — текст этапа 5.

| Тип параметра | Редактор | Запись |
| --- | --- | --- |
| `String` | поле ввода | текст как есть, проверка длины |
| `Double`, `Integer` | поле ввода с единицей `Editor.Unit` справа (`кВт`) | число с точкой или запятой, проверка `Min/Max`; у `Integer` — целое |
| `Enum` | выпадающий список подписей элементов; ввод своего значения — при `Editor.AllowCustom` | ключ элемента (`A` для «A (L1)»), а не подпись; значение не из списка без `AllowCustom` — ошибка ввода |
| `Boolean` | флажок, третье состояние — «Разное» | сразу по щелчку |
| `CalculatedString`, `Editor.ReadOnly`, параметры вне схемы, «Прежний формат» | нет (только чтение) | — |

- **Enter** или **выход из ячейки** (щелчок по другой строке, `Tab`) записывают значение, только если
  текст изменён. **Esc** возвращает показанное значение, ничего не записывая. **F2**, **Enter** на строке
  без дочерних строк или щелчок по значению выделенной строки ставят курсор в редактор.
- Выбор элемента в выпадающем списке записывается сразу при закрытии списка.
- **«Разное»**: редактор пуст, заполнитель «Разное» серым курсивом. Посещение без ввода ничего не
  пишет — значения объектов остаются разными; введённый текст (в том числе буквально `Разное`)
  записывается во все объекты. Заполнитель исчезает, как только текст изменён: набранный и стёртый
  текст — это уже данные (пустое значение), а не «Разное»; Esc возвращает заполнитель.
- Пустой текст у нестрокового параметра восстанавливает умолчание: значение удаляется из XDATA
  (раздел 6.2), строка показывает умолчание с `○`. Пустой текст в ячейке таблицы — ошибка ввода.
- **Ошибка ввода** («Ошибка ввода: Power: значение меньше min.», «Ошибка ввода: Phase: «L4» нет в списке.») — красное
  сообщение над VST, транзакция не открывается, редактор показывает прежнее значение.
- **Ошибка записи** (транзакция отменена, лимит 255 байт/16 КБ, объект заблокирован) — красное
  «Ошибка записи: …»; выделение перечитывается, значения остаются прежними, выделенная строка
  сохраняется. Следующее успешное чтение убирает сообщение.

## Флажки

- Флажок колонки 2 (`Boolean`-параметр или ячейка `✎`) и флажок колонки 3 строки таблицы
  (`Boolean`-колонка, например `Mat_InSpec`) записывают новое состояние по щелчку или **Пробелу**.
- Трёхпозиционный флажок «Разное» по щелчку становится «включён» во всех объектах; остальные
  различающиеся значения строки не трогаются.

## Таблицы: `×`, `✎`, `+ Добавить`

| Кнопка | Действие |
| --- | --- |
| `×` (колонка 0) | Удаляет строку таблицы по ключу из всех объектов. У значения вне шаблона («Дополнительные») или вне схемы («Не описаны в схеме») удаляет это значение. |
| `✎` (колонка 0) | Раскрывает ячейки строки дочерними строками «колонка — значение» с редакторами по типу колонки; повторный `✎` сворачивает. Строка остаётся раскрытой после записи. |
| `+ Добавить` (колонка 4 узла таблицы или категории) | Добавляет строку с новым уникальным ключом («Новая строка», «Новая строка 2», для чисел — max + 1, для `Enum` — первый свободный элемент) во все объекты; в категории `GroupBy` строка получает значение категории. Новая строка раскрывается `✎`, курсор — в ячейке ключа для переименования. |

Новый ключ переименовывает строку во всех объектах и должен остаться уникальным (раздел 4.2):
повтор ключа — ошибка ввода. Изменение колонки `GroupBy` переносит строку в другую категорию.
Строка, которой нет у части объектов («Разное»), после записи ячейки появляется во всех объектах.
Если переименование не записалось (ошибка записи), строка остаётся раскрытой и выделенной под прежним
ключом. Редактируются только колонки, объявленные в схеме таблицы; ячейки других колонок (например,
параметр вне таблицы, записанный в строку) — только чтение.

## «+ Параметр» (раздел 8.4)

Кнопка `+` панели открывает меню скалярных параметров схемы, которых ещё нет в дереве
(подпись `Caption (Id)`). Выбранный параметр записывается во все объекты со значением по
умолчанию (или пустым значением своего типа, с учётом `Min`) и появляется в группе
«Дополнительные» выделенным, с курсором в редакторе. Таблицы, колонки таблиц и `CalculatedString`
в меню не входят; если добавлять нечего — недоступный пункт «Все параметры схемы уже показаны».
`×` такого параметра удаляет его значение; параметр шаблона `×` не имеет — его значение очищается
пустым вводом.

## Запись и пересчёт формул

```text
PropertyGridViewModel.Commit/SetFlag/DeleteRow/AddRow/AddParameter
  → SelectionEdit (SetParameter / RemoveParameter / SetTableCell / AddTableRow / DeleteTableRow)
  → SelectionViewModel.RequestEdit → EditRequested
  → SelectionController.Write → ISelectionWriter.WriteSelection (XDataWriter, одна транзакция)
  → перечитывание выделения и кэша значений → Apply → пересчёт CalculatedString → перестроение VST
```

- Записывается только изменённое поле; остальные значения каждого объекта (в том числе «Разное»,
  чужие RegApp и данные вне схемы) сохраняются — это проверяют перенесённые тесты.
- Запись синхронна: после Enter дерево уже перестроено, раскрытие, прокрутка и выделенная строка
  восстанавливаются по её пути (`p:ID`, `t:…/r:Ключ/f:Колонка`).
- Поздняя запись (выход из ячейки уже после `×` или после записи другой строки) относится к той же
  строке нового дерева по её пути; если строки больше нет, текст отбрасывается — удалённая строка
  не возвращается. Флажок, `×` и `+ Добавить` на строке прежнего дерева ничего не делают.
- Формулы, зависящие от изменённого параметра, пересчитываются сразу (`ЩУ1` + `7` → `ЩУ1.7`);
  `Persist`-значения записываются той же транзакцией (этап 4).
- В AutoCAD одна запись — один шаг Undo: `AutoCadXDataWriteTransaction` блокирует документ
  командой `XDATAPALETTEEDIT` («Изменение XDATA») и открывает одну транзакцию на всё выделение.
- Без писателя выделения (предпросмотр) VST только показывает значения. Если в выделении есть объект
  формата v1 или версии новее v2, весь VST — только чтение с сообщением «Есть объекты в формате v1
  или более новой версии: только чтение.» (перенос — `VELEC_MIGRATE`, этап 9).

## Проверка

```bash
DOTNET_ROLL_FORWARD=Major dotnet test tests/AcadPaletteSetXData.Core.Tests -c Release
# Windows: рендеры в каталог
dotnet run --project experiments/AcadPaletteSetXData.WpfSmoke -c Release -f net48 -- artifacts/screenshots/net48
```

WPF smoke (CI, net48 и net8) в настоящем `PropertyGridView` проверяет: редактор только у выделенной
строки; Enter без ввода не пишет «Разное», заполнитель «Разное» исчезает после ввода и стирания и
возвращается по Esc; ввод + Enter пишет все объекты; единица `кВт`; Esc;
красную ошибку ввода `-1`; запись `Enum` из списка; трёхпозиционный флажок; `✎` и запись ячейки;
`+ Добавить` с выделением ключа и `×`; меню «+ Параметр» и запись выбранного параметра; ошибку
записи с сохранением значений и выделения. Ручная проверка Undo/Redo в AutoCAD —
[autocad-verification.md](autocad-verification.md#tzxdata-этап-6-редактирование-в-vst), рендеры —
[screenshots](screenshots/README.md).

## Ограничения этапа

- Undo/Redo, фокус клавиатуры внутри нативной `PaletteSet` и запись в живую DWG CI не проверяет —
  только ручной сценарий в AutoCAD.
- При повторяющихся ключах строк в одном объекте (нарушение раздела 4.2) запись ячейки меняет все
  строки с этим ключом, а `×` удаляет их все.
- «+ Параметр» добавляет только скалярные параметры; новые таблицы появляются с шаблоном (этап 7).
- После ошибки ввода редактор показывает прежнее значение, введённый текст нужно набрать заново.
- Рендер меню «+ Параметр» собран из двух изображений (палитра и всплывающее меню): WPF рисует
  `ContextMenu` в отдельном окне.
